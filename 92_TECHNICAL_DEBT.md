# Neith — Technical Debt Register

**Status:** No verified entries as of 2026-09-29

A proposed feature, unanswered architecture question, or absent evidence is not technical debt. Enter debt only after observing a real code or operational compromise with a cost of continuing it.

## Entry template
- ID, component, owner, date discovered
- Evidence: repo/commit, incident, test, or metric
- Current behavior and intended invariant
- Business/user impact and risk of postponement
- Workaround and remediation options
- Dependencies, estimate, priority, target milestone
- Verification and closure evidence

Review debt during roadmap planning. Link security-critical defects to the defect/incident process as well; a register must not hide urgent work.
